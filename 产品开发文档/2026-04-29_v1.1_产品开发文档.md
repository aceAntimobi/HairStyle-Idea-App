# Hairstyle v1.1 产品开发文档

- 日期：2026-04-29
- 版本：v1.1
- 上游依据：`docs/hairstyle-product-prd.md`
- 迭代目标：在现有 Flutter 版本基础上补齐 PRD 中 P0/P1 的产品完整度，让 App 从“首页和编辑器 Demo”升级为“可验收的换发型产品雏形”。

## 1. 产品概述

### 产品目标

围绕“AI 换发型”主链路，补齐用户可感知的产品闭环：进入首页、浏览发现、进入工作室、选择照片/模特、试戴发型/眼镜/发色、保存结果、在记录页查看、进入会员页理解商业化权益。

### 目标用户

- 准备换发型、染发、剪刘海的女性用户。
- 需要自拍、头像、社媒妆发灵感的轻编辑用户。
- 对年龄变化、性别变化、换脸、卡通脸等娱乐效果感兴趣的用户。

### 核心价值

- 低门槛：默认模特可直接试用。
- 可编辑：支持发型、眼镜、发色、背景、光效。
- 可闭环：保存后进入本地历史记录。
- 可商业化：会员页承接 Pro 权益、高清保存、去广告等策略。

### 版本范围

v1.1 优先做 UI 与本地能力闭环，不接真实云端 AI、真实订阅、真实广告。所有商业化和 AI 扩展页以产品化 UI、Mock 权益和可点击流程落地，避免空入口。

## 2. 功能框架

### 一级功能模块

| 模块 | v1.1 范围 |
|---|---|
| 换发型首页 | 维持参考图风格，强化入口跳转和数据展示 |
| 发现页 | 增加年龄、性别、美颜、换脸、卡通脸、男士、儿童、古风等内容承载 |
| 工作室 | 保留发型/眼镜/发色/背景/光效编辑，补充状态反馈 |
| 历史记录 | 保存结果写入本地文件，记录页读取并展示 |
| 我的/会员 | 新增会员页，展示权益、套餐、恢复购买、合规入口 |
| 扩展功能 | 新增通用 AI 功能页，用于年龄变化、性别变化、美颜、换脸、卡通脸等入口 |

### MVP 范围

- 本地历史记录持久化。
- 保存结果同步写入 App 文档目录和系统相册。
- 会员页完整 UI。
- 发现页信息流扩容。
- 扩展 AI 功能页占位但不空白。
- Flutter analyze/test/build 通过。

### 非 MVP 范围

- 真实 Google Play Billing。
- 真实 AdMob 激励广告。
- 真实云端年龄变化/性别变化/换脸推理。
- 多语言全量翻译。

## 3. 页面与流程设计

### 页面地图

| 页面 | 说明 |
|---|---|
| 首页/换发型 | 主工作台入口 |
| 发现 | 多功能内容流和素材专题 |
| 记录 | 本地保存结果历史 |
| 我的 | 会员、帮助、隐私入口 |
| TryOnStudioPage | 换发型编辑器 |
| GalleryPage | 素材图库 |
| MembershipPage | 会员权益页 |
| AiFeaturePage | 年龄/性别/美颜/换脸/卡通脸通用功能页 |

### 核心路径

1. 首页点击生成发型进入工作室。
2. 工作室选择模特/相册/相机。
3. 选择发型/眼镜/发色并微调。
4. 点击保存。
5. 保存到相册，同时写入本地记录。
6. 回到记录页查看缩略图，并可重新进入工作室。

### 异常路径

- 权限拒绝：弹 SnackBar 提示，不闪退。
- 保存失败：提示失败，不写入记录。
- 本地记录读取失败：自动回退为空记录。
- 功能未接入真实 AI：页面明确说明“当前为本地预览/即将接入”。

## 4. 风格设计

### 设计关键词

女性化、美妆、紫粉渐变、清透白卡、圆角胶囊、轻阴影、杂志感图片。

### 颜色与氛围

沿用 PRD 的浅底 + 紫粉渐变。新页面统一使用 `#FAF8FF` 背景、`#8B5CFF` 主色、`#D162EF` 辅色。

### 组件基调

- 主 CTA：大圆角渐变按钮。
- 功能卡：白色圆角卡片 + 渐变图标底。
- 历史记录：图片卡 + 功能标签 + 时间。
- 会员页：顶部渐变权益卡 + 套餐卡 + 权益列表。

## 5. 技术方案

### Flutter 项目结构

当前项目为单文件原型：`lib/main.dart`。v1.1 继续在单文件内迭代，避免中途大规模拆文件引入风险。后续 v1.2 可按页面拆分。

### 状态管理方案

- 首页 Tab 状态：`StatefulWidget` + `IndexedStack`。
- 历史记录：新增 `HistoryRepository`，使用 `ValueNotifier<List<HistoryRecord>>` 通知页面刷新。
- 工作室编辑状态：保留页面内局部 state。

### 路由方案

继续使用 `Navigator.push(MaterialPageRoute)`，新增会员页和 AI 功能页路由。

### 数据存储方案

- 使用 `path_provider` 获取应用文档目录。
- 保存图片副本到 `generated/` 目录。
- 记录元数据写入 `history_records.json`。

### 关键依赖包

| 包 | 用途 |
|---|---|
| `image_picker` | 相册/相机导入 |
| `permission_handler` | 权限请求 |
| `screenshot` | 画布截图导出 |
| `image_gallery_saver_plus` | 保存到系统相册 |
| `google_mlkit_face_detection` | 人脸检测与贴合 |
| `path_provider` | 本地历史记录和图片副本存储 |

## 6. 数据与接口

### 本地历史记录字段

| 字段 | 说明 |
|---|---|
| `id` | 记录 ID |
| `imagePath` | App 文档目录图片路径 |
| `feature` | 功能类型，如 `hair` |
| `title` | 展示标题 |
| `subtitle` | 选中素材或效果摘要 |
| `createdAt` | 创建时间 |

### 远程接口

v1.1 不接远程接口。

### 埋点方案

v1.1 不接 Firebase，仅在代码结构上保留触发点语义。后续接入时优先覆盖：保存成功、会员页展示、功能入口点击。

## 7. 开发计划

### 本轮任务

1. 新增本地历史记录模型与仓库。
2. 修改保存流程，保存成功后写入历史记录。
3. 重构记录页，从空状态升级为真实记录列表。
4. 新增会员页并串起首页/我的入口。
5. 扩容发现页，新增更多 PRD 功能入口。
6. 新增 AI 扩展功能页，保持风格一致。
7. 跑 `flutter analyze`、`flutter test`、`flutter build apk`。
8. 安装到模拟器并截图验收。

### 风险点

- Android 13+ 相册权限与旧版存储权限差异：保存失败时必须提示。
- 历史记录图片路径可能因文件删除失效：展示时需要容错。
- 单文件继续变大：v1.2 建议拆分页面和组件。

## 8. 测试与交付

### 自测范围

- 首页可打开。
- 发现页可滚动、功能入口可点击。
- 工作室可打开默认模特。
- 选择发型/眼镜/发色无崩溃。
- 保存后记录页展示新记录。
- 会员页可打开。

### 自动化测试范围

- `flutter analyze`
- `flutter test`
- `flutter build apk --debug`

### APK 构建方式

输出到 Flutter 默认路径，并复制到 `构建产物/`：

- `build/app/outputs/flutter-apk/app-debug.apk`
- `构建产物/hairstyle-v1.1-debug.apk`

### 模拟器验证方式

使用 adb 安装 debug APK，启动 `com.hair_flutter/.MainActivity`，截图保存到 `验收记录/`。

### 验收标准

- 构建通过。
- APK 可安装启动。
- 首页、发现、记录、我的、会员页、工作室都能打开。
- 保存成功时本地记录可见。
- 已知未接入真实云端 AI/订阅/广告必须明确记录。
