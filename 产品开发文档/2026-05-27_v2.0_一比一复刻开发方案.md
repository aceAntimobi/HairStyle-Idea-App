# Hairstyle v2.0 一比一复刻开发方案

- 日期: 2026-05-27
- 版本: v2.0
- 项目: Hairstyle / AI 换发型
- 目标: 以参考 App 为功能框架和业务逻辑基准，一比一还原核心流程；视觉风格重新设计为更现代的美妆影像工具。

## 1. 当前实现结论

当前 Flutter 版本只能算“可打开的本地 Demo”，不能算参考 App 复刻。

主要问题:

- 首页只是入口聚合，没有真实承载“选图 -> 选风格 -> 生成 -> 对比 -> 保存/分享”的完整工作台。
- 工作室是本地贴纸编辑器，发型/眼镜靠透明 PNG 叠加，不是参考 App 的 AI 生成逻辑。
- 年龄变化、性别变化、美颜、换脸、卡通脸只有入口页，没有真实生成流程。
- 会员页是 Mock 展示，没有订阅状态、付费拦截、恢复购买、权益生效逻辑。
- 广告、评分、分享、收藏、草稿、重新编辑等闭环缺失或只有提示。
- 历史记录只保存结果图路径，没有原图、生成参数、风格、提示词、任务状态，无法重新编辑。
- iOS 权限文案缺失；Android 权限提示也不够产品化。

因此 v2.0 不在现有 Demo 上小修小补，而是按参考 App 功能骨架重建页面、状态机和生成链路。

## 2. 产品目标

### 2.1 核心目标

让用户能在 3 步内完成一次真实 AI 形象生成:

1. 导入照片或使用默认模特。
2. 选择功能和风格模板。
3. 生成结果，并完成对比、保存、分享或再次编辑。

### 2.2 AI 方案

- 生图模型: Seedream。
- 提示词优化: DeepSeek。
- 本地素材: 继续保留参考 App 拆出的发型、眼镜、发色、背景、年龄、性别、卡通、换脸等资源，用作模板、预览图、默认模特和生成参数入口。
- 本地贴纸编辑: 保留为 fallback 和手动微调能力，但不再作为主生成逻辑。

### 2.3 版本边界

v2.0 目标是可验收的功能框架和真实生成闭环:

- 必须完成主链路、主要页面、任务状态、生成历史、保存分享、会员拦截。
- Seedream / DeepSeek 先通过可替换服务层接入，具体 Key 走环境配置。
- 真实 Google Play Billing / AdMob 可先做接口层和 Debug Mock，但业务状态机必须按真实流程写，不能只放静态页面。

## 4. 核心流程

### 4.1 换发型主流程

```text
打开 App
 -> 首页工作台
 -> 选择照片: 默认模特 / 相册 / 相机
 -> 人脸检测与照片预处理
 -> 选择发型分类: 推荐 / 长发 / 中长发 / 短发 / 刘海 / 男士 / 古风 / 儿童
 -> 选择模板
 -> DeepSeek 优化提示词
 -> Seedream 生成结果
 -> 结果页对比: 原图 / 效果图
 -> 保存 / 分享 / 继续编辑 / 换一款
 -> 写入历史记录
```

### 4.2 娱乐 AI 通用流程

```text
发现页/首页入口
 -> 进入功能页: 年龄 / 性别 / 美颜 / 换脸 / 卡通
 -> 选择模板或目标效果
 -> 导入照片或默认模特
 -> DeepSeek 输出结构化提示词
 -> Seedream 生成
 -> 结果页对比、保存、分享
 -> 写入历史，可重新编辑
```

### 4.3 付费拦截流程

```text
用户触发 Pro 模板 / 高清保存 / 免费次数耗尽
 -> 检查会员状态
 -> 会员: 继续
 -> 非会员: 会员页半屏/全屏弹出
 -> 订阅 / 激励广告 / 关闭
 -> 成功后继续原动作，失败或关闭保持原状态
```

### 4.4 保存分享流程

```text
点击保存/分享
 -> 检查结果是否已生成
 -> 检查会员与高清/水印策略
 -> 请求相册权限
 -> 导出图片
 -> 保存到系统相册
 -> 写入本地记录
 -> 分享时调起系统分享面板
 -> 触发评分/广告策略
```

## 6. 设计风格

### 6.1 关键词

高级美妆、AI 影像工具、干净、轻奢、柔和但不幼稚、结果图优先。

### 6.2 色彩

- 背景: `#F7F4F2` 暖灰白，减少廉价紫粉感。
- 主色: `#111111` / `#1D1A1A`，用于标题和核心按钮。
- 强调色: `#D9B77E` 香槟金，用于 Pro、选中态和权益。
- 辅助色: `#B86B77` 玫瑰豆沙，用于 AI、生成、女性化提示。
- 卡片: `#FFFFFF`，8-16 圆角，根据页面密度控制。
- 分割线: `#E8E1DC`。

### 6.3 组件原则

- 首页必须像工具，不做空洞营销页。
- 人像和结果图永远是首屏最大视觉中心。
- 所有功能入口都必须可点击，并进入真实流程或明确的生成任务页。
- Pro 标签、免费次数、生成状态必须显性展示。
- 按钮不使用大面积廉价渐变，主按钮以黑色/深色实底为主，Pro 用香槟金。
- 卡片圆角控制在 12-16，工具区 8-12，避免全屏胶囊化。

### 6.4 动效

- 生成中使用步骤进度和轻量 shimmer，不做夸张加载动画。
- 对比支持点击切换，后续可升级为滑杆。
- 模板选择使用轻微缩放和边框高亮。
- 页面切换保持 200ms 内，强调速度和确定性。

## 7. 技术方案

### 7.1 工程结构

v2.0 必须拆出基础分层，停止继续堆单文件:

```text
lib/
  main.dart
  app/
    app.dart
    router.dart
    theme.dart
  features/
    home/
    discover/
    editor/
    generation/
    history/
    membership/
    settings/
  core/
    models/
    services/
    repositories/
    widgets/
```

### 7.2 AI 服务层

```text
PromptService
  -> DeepSeek: 输入功能、模板、用户照片信息、风格参数
  -> 输出正向 prompt、负向 prompt、结构化生成参数

ImageGenerationService
  -> Seedream: 输入原图、prompt、模板参数、尺寸
  -> 输出任务 ID / 结果图 URL 或 bytes

GenerationRepository
  -> 管理任务状态: queued / optimizingPrompt / generating / succeeded / failed / cancelled
```

### 7.3 核心数据模型

- `StyleTemplate`: 模板 ID、功能、标题、预览图、是否 Pro、提示词标签。
- `GenerationSession`: 原图、功能、模板、prompt、seed、状态、结果图、错误。
- `HistoryRecord`: 原图、本地结果图、功能、模板、prompt、seed、是否收藏、创建时间。
- `MembershipState`: 是否会员、权益、免费次数、临时广告解锁。
- `UsageQuota`: 每日生成次数、高清保存次数、广告解锁次数。

### 7.4 本地存储

- `shared_preferences`: 轻量状态、免费次数、会员 Mock 状态、评分频控。
- App documents: 原图副本、结果图、缩略图。
- JSON 或 SQLite: 历史记录、模板收藏、草稿。v2.0 可以先用 JSON，后续转 SQLite。

### 7.5 接口配置

通过环境变量或运行参数配置:

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL`
- `SEEDREAM_API_KEY`
- `SEEDREAM_BASE_URL`
- `AI_IMAGE_PROVIDER=seedream`
- `PROMPT_PROVIDER=deepseek`

### 7.6 关键依赖建议

- `http` 或 `dio`: AI 接口请求。
- `shared_preferences`: 本地轻量状态。
- `share_plus`: 系统分享。
- `image_picker`: 相机/相册。
- `permission_handler`: 权限。
- `path_provider`: 本地文件。
- `image_gallery_saver_plus`: 保存相册。
- `google_mlkit_face_detection`: 人脸检测和本地 fallback。

## 9. 验收标准

v2.0 不以“能打开页面”为验收，必须按流程验收:

- 首页可直接完成换发型生成，不依赖隐藏入口。
- 每个一级功能入口都进入真实流程页。
- DeepSeek 提示词优化有请求、响应、失败兜底。
- Seedream 生图有任务状态、成功结果、失败重试。
- 保存、分享、历史、重新编辑完整。
- 非会员触发 Pro 模板/高清保存时进入付费拦截。
- 会员页至少具备可测试状态机，即使真实 Billing 后接。
- Android 模拟器核心流程可跑通。
- 不再出现“只有入口，没有流程”的页面。

## 10. 待确认

- Seedream 具体服务商接口形态: 是否兼容 OpenAI 风格接口，或需要单独 SDK/REST 参数。
- DeepSeek 使用模型: `deepseek-chat` 还是指定其他模型。
- 生图是否要求严格保留用户原脸；如果要求，需要 Seedream 支持 image-to-image / reference image / face consistency 参数。
- 免费次数、Pro 模板范围、水印策略是否按参考 App 原样还原，还是按新商业策略调整。
